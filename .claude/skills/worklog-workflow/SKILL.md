# 작업 일지

사용자 프롬프트 내용과 실제 수행·검증 결과 요약을 `docs/worklog/YYYY-MM.md`에 기록한다.

## 절차

1. 오늘 날짜로 `docs/worklog/YYYY-MM.md` 경로를 정한다.
2. 파일이 없으면 `# YYYY-MM 작업 일지` 제목으로 만든다.
3. 오늘 날짜의 `## YYYY-MM-DD` 섹션이 없으면 파일 맨 아래에 추가한다.
4. 한 번에 전송된 사용자 메시지 하나를 줄 수와 관계없이 프롬프트 하나로 보고, 항목 하나를 오늘 날짜 섹션 아래에 추가한다.
5. 같은 사용자 메시지를 이미 기록했으면 중복해서 추가하지 않는다.
6. 과거 항목은 수정하지 않는다.

## 형식

```markdown
## YYYY-MM-DD

### <사용자 요청 한 줄 요약>

입력:
> <장문 코드·개인정보·인증정보를 제외한 프롬프트 첫 줄>
>
> <프롬프트 다음 줄>

출력:
- <실제 수행 결과와 검증 결과 요약>

다음:
- <미완료 작업이 있을 때만>
```

## 원칙

- 제목은 프롬프트를 한 문장으로 요약한다.
- 한 번에 전송된 사용자 메시지 하나를 프롬프트 하나로 본다.
- 여러 문단·제목·목록·코드가 있어도 항목을 나누지 않는다.
- `입력`에는 요청 의도가 바뀌지 않도록 프롬프트 내용을 인용한다.
- 입력을 인용할 때 내용이 있는 줄은 `> `, 빈 줄은 `>`로 시작한다.
- 장문 코드와 파일 본문은 복사하지 않고, 개인정보와 인증정보는 기록하지 않는다.
- `출력`은 실제 수행 결과와 검증 결과를 1~3개 항목으로 요약한다.
- `다음`은 미완료 작업이 있을 때만 추가하고, 완료됐으면 항목 자체를 만들지 않는다.
- 월별 파일의 아래쪽에 새 기록을 추가한다.
- 작업일지는 `AGENTS.md`나 `CLAUDE.md`에 적지 않는다.
