# Agent Memory 사용 규칙

`mcp__agentmemory__*` 도구(memory_recall / memory_smart_search / memory_save / memory_governance_delete 등)를 이 저장소에서 사용할 때의 규율.

## 프로젝트 식별

- 이 저장소의 Agent Memory 범위는 `<project-slug>`으로 고정한다.
- 프로젝트별 메모리의 저장·검색 시 항상 `project: <project-slug>`을 지정한다.
- slug는 저장소 간 공유하지 않는다. 변경이 필요하면 기존 메모리의 처리 방침을 먼저 정한다.

## 로드 규칙

1. 새 에이전트 세션의 첫 의미 있는 작업 전에, 현재 요청·관련 파일·기능명을 검색어로 `<project-slug>` 범위의 메모리를 조회한다.
2. 검색 결과 중 현재 작업과 직접 관련 있는 결정·제약·미해결 사항만 컨텍스트로 사용한다.
3. 결과가 없으면 추측하지 않고 새 작업으로 진행한다.
4. 오래된 메모리와 현재 코드·사용자 지시가 충돌하면 현재 코드·사용자 지시를 우선한다.

## 저장 규칙

아래처럼 미래 작업에 재사용 가치가 있는 내용만 저장한다.

- 아키텍처·구현 결정과 그 이유
- 반복적으로 발생한 문제와 검증된 해결책
- 프로젝트 고유의 제약, 관례, 외부 연동 정보
- 미해결 이슈와 다음 작업자가 알아야 할 상태

**저장하지 않는 것:** 일시적 진행 상황, 일반적인 설명, 코드에서 즉시 확인 가능한 사실.

저장 시 함께 기록한다: 내용, 구체적인 검색 태그(concepts), 관련 파일 경로.

메모리는 사실과 결정만 기록한다 — 추측, 확인되지 않은 원인, 민감정보는 저장하지 않는다.

## 보안·정리 규칙

- API 키, 비밀번호, 토큰, 개인정보, 비공개 원문은 저장하지 않는다.
- 잘못되었거나 더 이상 유효하지 않은 메모리를 삭제하기 전에는 대상 메모리를 사용자에게 보여주고 명시적 승인을 받는다.
