# PRD Writer

`docs/prd/` 아래에 스킬·에이전트·기능 등 **개발할 대상의 계획서**를 작성·갱신한다. 초안과 모든 후속 결정을 `## 개발 vN` 시리즈로 한 파일에 누적해 결정 흐름을 추적할 수 있게 한다.

스킬 자산:

- 문서 스켈레톤: [template.md](template.md)
- 참고 예시: [../../../prd/prd-docs.md](../../../prd/prd-docs.md), [../../../prd/dtm_v1.md](../../../prd/dtm_v1.md)

## When to invoke

| 사용자 요청                                 | 동작                                         |
| ------------------------------------------- | -------------------------------------------- |
| 새 스킬·에이전트·기능 PRD를 만들어 달라   | 신규 파일 생성,`## 개발 v1` 작성           |
| "개발 문서 작성", "prd 작성" 등 트리거 어구 | 신규 또는 갱신 결정                          |
| 기존 PRD에 수정·추가 사항 반영             | 본문 보존, 파일 끝에 다음`## 개발 vN` 추가 |
| 코드 사용법·API 문서                       | 사용하지 않는다 →`feature-docs` 스킬      |
| 변경 이력만 요약                            | 사용하지 않는다 → git log                   |

대상이 모호하면 (PRD인지 사용법 문서인지, 신규인지 갱신인지) 작성 전에 사용자에게 확인한다.

## Procedure

1. **요청 분류** — 신규 PRD인지, 기존 PRD에 대한 수정 요청인지 판단.
2. **출력 파일 경로 결정**
   - **참조 문서가 있는 경우** (예: `prd/prd-docs.md`, `prompt-login.md` 같은 유저 요청 사항 파일을 참고로 받음):
     - 참조 파일명에서 확장자 제거.
     - `mine`·`prompt`·`docs` 토큰을 (구분자 `-`/`_` 포함) 삭제한다.
     - 결과 뒤에 `-prd`를 붙여 `docs/prd/<정리된_이름>-prd.md`로 저장한다.
     - 예: `prd/prd-docs.md` → `docs/prd/prd-prd.md`
     - 예: `prompt-login-flow.md` → `docs/prd/login-flow-prd.md`
     - 예: `feature-coupon.md` → `docs/prd/feature-coupon-prd.md`
   - **참조 문서가 없는 경우**: 사용자에게 주제 슬러그를 받아 `docs/prd/<주제>-prd.md`로 저장한다.
   - **갱신 시**: 기존 파일을 그대로 사용한다. 새 파일을 만들지 않는다.
3. **초안 작성 (신규)** — [template.md](template.md)를 기반으로 `## 개요`, `## 개발 v1`(트리거·범위·산출물·동작 규칙 등) 섹션을 채운다. 참조 문서의 **개발 계획**에 해당하는 요구사항만 v1에 반영한다. 사용법·API 가이드 같은 운영 단계 콘텐츠는 제외한다.
4. **수정 누적 (갱신)** — 위쪽 본문은 **건드리지 않는다**. 파일 최하단에 다음 번호의 `## 개발 vN` 섹션을 추가한다 (`v1`만 있으면 `v2`, `v2`까지 있으면 `v3` …).
   - 변경 항목은 번호 목록으로 명시한다.
   - 각 항목은 "무엇을 어떻게 바꾸겠다"가 한 줄로 보이게 쓴다.
5. **링크 검증** — 본문에 적은 `[경로](경로)` 링크가 실제 존재하는지 확인.
6. **보고** — 만든/갱신한 파일 경로와 추가된 섹션(`개발 v1` / `개발 vN`)을 1~3줄로 보고.

## Writing principles

1. **PRD는 "무엇을 만들 것인가"의 합의 문서**다 — 트리거, 범위, 결과물, 제약을 적는다. **사용법·API 호출 예시 등은 적지 않는다** (개발 계획 외 운영 콘텐츠는 제외).
2. **초안 본문은 불변**. 합의된 내용을 덮어쓰지 않고, 변경은 항상 다음 번호의 `## 개발 vN`으로 누적한다.
3. **수정 섹션은 결정 그 자체**를 적는다 — "이렇게 바꾼다"의 명령형. 구현 세부 코드는 적지 않는다.
4. **한국어로 작성**한다. 식별자·파일명·트리거 어구는 영어 그대로.
5. **링크는 마크다운 상대 경로**로. 다른 PRD나 스킬 폴더를 가리킬 때 사용.
6. **PR 번호·날짜·작성자 메타는 본문에 적지 않는다** — git이 한다.

## Anti-patterns

- 수정 요청을 받고 위쪽 본문을 직접 고친다 → 항상 다음 `## 개발 vN`으로 누적.
- 하나의 PRD를 여러 파일로 쪼갠다 (`*-v2.md` 같은 새 파일 생성 금지).
- 참조 문서 이름을 그대로 써서 `prompt-*.md` / `*-docs.md`로 출력한다 → 토큰 제거 후 `-prd` 접미사 사용.
- `plan-` 접두어를 사용한다 (구 v1 규약, v2부터 폐기).
- 사용법(API·호출 예시·튜토리얼)을 PRD에 적는다 → `feature-docs` 스킬에서 처리.
- "v1.0.0" 같은 SemVer를 본문에 박는다.
- 트리거·범위가 비어 있는 모호한 PRD를 만든다.
