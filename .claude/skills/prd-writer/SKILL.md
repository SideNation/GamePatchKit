# PRD 작성

PRD에 목적, 요구사항, 완료 조건을 반드시 포함한다. 그 밖의 구성과 상세도는 구현 대상을 명확히 합의할 수 있도록 요청과 프로젝트 맥락에 맞게 판단한다.

## 절차

1. 기존 PRD가 있으면 그 파일을 사용하고, 없으면 `docs/prd/<주제>-prd.md`에 만든다.
2. 사용자 요청과 관련 자료에서 목적, 요구사항, 완료 조건을 확인한다.
3. 기존 프로젝트라면 관련 문서와 프로젝트 파일에서 현재 동작, 제약과 환경을 확인한다.
4. 구현 범위와 완료 판단을 명확히 하는 데 필요한 추가 항목을 결정한다.
5. 확인된 내용으로 현재 PRD를 작성하거나 갱신한다.
6. 필수 항목이 모두 포함됐고 모든 내용이 사용자 요청이나 확인한 자료에 근거하는지 검토한다.

## 형식

```markdown
# <PRD 제목>

## 목적

무엇을 왜 만드는지 설명한다.

## 요구사항

- 구현해야 하는 동작과 조건

## 완료 조건

- 완료 여부를 확인할 수 있는 기준
```

위 세 섹션은 반드시 포함한다. 그 밖의 섹션은 정해진 체크리스트가 아니며, 문서를 이해하고 구현·검증하는 데 도움이 될 때 판단해 추가한다.

예: 배경, 대상 사용자, 사용 흐름, 범위, 제약, 의존성, 개발 환경, 위험, 제외 범위, 확인할 사항

## 원칙

- 목적, 요구사항, 완료 조건은 최소 구성이 아니라 반드시 포함해야 하는 기준이다.
- 나머지 구성과 상세도는 요청의 규모, 프로젝트 상태와 독자가 판단하는 데 필요한 정보에 맞춰 결정한다.
- 예시 섹션을 모두 추가하지 않는다.
- 사용자 요청과 프로젝트에서 확인된 사실만 적는다.
- 확인되지 않은 기능, 제약, 기술 선택과 버전을 만들지 않는다.
- 중요한 정보가 확인되지 않았으면 사실처럼 단정하지 않고 필요한 경우 `확인 필요`로 표시한다.
- 비어 있는 선택 섹션이나 불필요한 `없음` 항목을 만들지 않는다.
- 변경 이력을 누적하지 않고 현재 합의 내용으로 갱신한다.
- 요구사항을 이해하거나 검증하는 데 필요하지 않은 구현 세부 코드와 작업 진행 기록은 적지 않는다.
- 한국어로 작성하고 코드·제품·기술 이름은 원문을 유지한다.
