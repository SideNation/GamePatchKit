# 최소 PRD 작성

PRD에 구현 대상을 합의하는 데 꼭 필요한 내용만 작성한다.

## 절차

1. 기존 PRD가 있으면 그 파일을 사용하고, 없으면 `docs/prd/<주제>-prd.md`에 만든다.
2. 사용자 요청과 관련 자료에서 목적, 요구사항, 완료 조건을 확인한다.
3. 구현에 영향을 주는 버전이나 플랫폼이 있으면 프로젝트 파일에서 확인한다.
4. 확인된 내용으로 현재 PRD를 작성하거나 갱신한다.
5. 모든 항목이 사용자 요청이나 확인한 자료에 근거하는지 검토한다.

## 형식

```markdown
# <PRD 제목>

## 목적

무엇을 왜 만드는지 설명한다.

## 요구사항

- 구현해야 하는 동작과 조건

## 완료 조건

- 완료 여부를 확인할 수 있는 기준
```

다음 섹션은 해당 내용이 있을 때만 추가한다.

- `개발 환경`: 구현을 제약하는 런타임·엔진 버전 또는 대상 플랫폼
- `제외 범위`: 사용자가 명시한 제외 사항

## 원칙

- 사용자 요청과 프로젝트에서 확인된 사실만 적는다.
- 확인되지 않은 기능, 제약, 기술 선택과 버전을 만들지 않는다.
- 비어 있는 선택 섹션이나 `없음`, `미정` 항목을 만들지 않는다.
- 변경 이력을 누적하지 않고 현재 합의 내용으로 갱신한다.
- 구현 세부 코드와 작업 진행 기록은 적지 않는다.
- 한국어로 작성하고 코드·제품·기술 이름은 원문을 유지한다.
