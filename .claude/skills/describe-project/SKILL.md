# 프로젝트 및 기능 설명

프로젝트가 하는 일과 주요 기능의 사용법을 `docs/project-description.md` 한 파일에 정리한다.

## 절차

1. 기존 `docs/project-description.md`가 있으면 읽는다.
2. README, manifest, 주요 진입점, 공개 API와 핵심 기능 코드를 우선 확인한다.
3. 프로젝트 전체 요청이면 개요·주요 기능·전체 동작 흐름을 작성한다.
4. 특정 기능 문서 요청이면 해당 기능 섹션만 작성하거나 갱신한다.
5. 각 기능에는 하는 일, 사용 방법, 동작 결과를 필요한 만큼 적는다.
6. 작성한 내용이 확인한 코드나 문서에 근거하는지 검토한다.

## 출력 형식

```markdown
# <프로젝트 이름>

## 프로젝트 개요

이 프로젝트가 무엇이며 어떤 목적으로 사용되는지 설명한다.

## 주요 기능

### <기능 이름>

- 하는 일:
- 사용 방법:
- 동작 결과:
- 참고: <!-- 필요한 제약이나 오류가 있을 때만 -->

## 전체 동작 흐름

프로젝트가 시작되어 주요 기능이 실행되고 결과를 만드는 과정을 순서대로 설명한다.
```

기능 수에 맞춰 `### <기능 이름>` 섹션을 반복한다. 직접 사용하는 기능이 아니면 `사용 방법`을 생략하고, 필요한 경우에만 최소 코드 예시를 추가한다.

## 작성 원칙

1. 코드와 문서에서 확인되는 실제 동작만 적는다.
2. 클래스·메서드·파일 목록보다 사용자가 이해할 수 있는 기능 단위로 설명한다.
3. 요청하지 않은 기능 문서를 별도 파일로 만들지 않는다.
4. 비어 있거나 필요 없는 항목과 섹션은 만들지 않는다.
5. 내부 구현은 기능과 사용법을 이해하는 데 필요한 범위까지만 적는다.
6. 작업 기록, 진행률, 미완료 작업, 향후 계획과 변경 이력은 적지 않는다.
7. 기존 설명이 현재 동작과 다르면 고치고 과거 설명을 누적하지 않는다.
8. 한국어로 작성하고 코드·경로·식별자는 원문을 유지한다.

## 금지

- README만 바꿔 쓰고 실제 동작을 확인하지 않는다.
- 클래스·폴더 구조를 프로젝트 기능처럼 나열한다.
- 아직 구현되지 않은 기능이나 계획을 현재 기능처럼 적는다.
- 작업일지나 세션 인수인계 내용을 포함한다.
