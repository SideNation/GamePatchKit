### Unity 패치 클라이언트 UPM 패키지 구현 (grilling 자체 판단 후 진행)

#### 사용자 입력

> 계속 진행해줘. 사람이 실시간으로 답하지 않는 환경이니, Q4 이후 남은 grilling 질문들도 지금까지 한 것처럼 네가 직접 근거를 조사해서 판단하고 계속 진행해줘.

#### 작업 결과

- 수행: grilling Q1~Q3은 제시한 권장안(Unity 6 전용·Standalone/Android/iOS 목표, ZstdSharp.Port 0.8.8 managed DLL 동봉, UPM Git URL 배포·`com.sidenation.gamepatchkit`)을 채택하고 Q4~Q9는 조사한 근거로 판단해 `docs/design/game-patch-kit-unity-client-design.md`에 기록했다. UPM 패키지 `src/GamePatchKit.Unity`(0.1.9)에 `PatchClient(baseUrl, rootPath).SyncAsync(releaseVersion, cancellationToken)`, `PatchSyncResult`, `PatchClientException`과 CLI `ManifestStore`·`DataExtractor`·`RelativePathValidator`·매니페스트 모델을 .NET Standard 2.1/C# 9로 옮긴 `Runtime/Core`, `ZstdSharp.dll`·`System.Runtime.CompilerServices.Unsafe.dll`(ZstdSharp netstandard2.1 의존성, Unity Player 프로필에 없음), `link.xml`, 서드파티 고지를 추가했다. 네트워크는 메인 스레드 `UnityWebRequest`(`DownloadHandlerFile`), 해시·해제는 `Task.Run`이며 취소는 캡처한 `SynchronizationContext`로 `Abort`를 보낸다. 로컬 배치·델타 규칙은 `gpk sync`와 같고 포인터는 읽지 않는다. Unity .NET Standard 2.1 프로필에 `File.Move(…, overwrite)`가 없어 `FileMover.MoveReplacing`(대상 있으면 `File.Replace`)으로 교체했다. 검증용 호스트 프로젝트 `unity/GamePatchKit.Unity.Host`(6000.4.4f1)와 스크립트(`generate-fixtures.sh`로 실제 `gpk build` 산출물 픽스처 생성, `run-tests.sh` PlayMode, `run-player-tests.sh` StandaloneOSX IL2CPP)를 추가하고, 루프백 `HttpListener`로 최초 동기화·no-op·증분·롤백·checksum 불일치·404·releaseVersion 불일치·잘못된 매니페스트·이전 세대 보존·해제 실패 후 수렴·아카이브 다운로드 중 취소·생성자 검증 12개 테스트를 작성했다. 사용법 문서 `docs/unity/patch-client.md`, README·`docs/project-description.md`·패키지 README를 갱신했다. Codex adversarial 검토(`gpt-5.6-sol`) 3회: 1차 Blocker 3·High 4·Medium 4 중 F1(해제 시작 시 이전 `manifest.json` 삭제로 실패 트리 오인 방지), F2(`File.Replace`), F3(설치 태그 `v0.1.9`), F5(해제 루프·매니페스트 쓰기 직전 취소 확인), F7(테스트 3개 추가), F11(I/O·zstd 예외를 `PatchClientException`으로 감싸고 `InnerException` 보존)을 적용하고 F4(크기 기반 재사용)·F6(symlink)·F8(동시 호출 락)·F9(`Skip` EOF)·F10(대소문자 충돌)은 CLI와 같은 설계 전제로 거부해 문서화했다. 2차 Medium 2건(취소 테스트 게이트, 혼합 트리 수렴 테스트)을 적용했고 3차는 Low 2건(테스트 격리)만 남아 보류했다.
- 검증: ZstdSharp 0.8.8이 CLI(`NativeCompressions`)가 만든 zstd 아카이브·파일 객체를 바이트 단위로 같게 풀고 변조 프레임을 거부하는 것을 .NET 콘솔로 확인했다. Unity 6000.4.4f1 에디터 PlayMode 12/12 통과, macOS IL2CPP Player(`il2cpp --convert-to-cpp` 확인) 12/12 통과. 컴파일 경고 0, `git diff --check` 통과, 호스트 `ProjectSettings`의 scripting backend는 Mono 기본값 유지. ### Unity 프로젝트에서 직접 시험할 수 있는 샘플 씬 추가

#### 사용자 입력

> unity 프로젝트에서 내가 직접 테스트해보게 만들어 줘

#### 작업 결과

- 수행: 호스트 프로젝트에 수동 시험 경로를 추가했다. `Assets/PatchClientSample/PatchClientSample.cs`(IMGUI 패널 MonoBehaviour: Base URL·releaseVersion 입력, Sync·Cancel·Delete local root 버튼, 로컬 `manifest.json` 유무와 `data` 트리 목록, 로그), 코드로 씬을 만드는 `Assets/Editor/PatchClientSampleSceneBuilder.cs`(메뉴 `GamePatchKit > Rebuild Sample Scene`, batchmode `-executeMethod` 지원), 픽스처 버킷을 정적 HTTP로 띄우는 `scripts/serve-fixtures.sh`를 추가하고 씬을 Build Settings에 등록했다. `docs/unity/patch-client.md`에 "직접 테스트" 절(픽스처 서버 실행 → 씬 열기 → 세대 0·1·롤백 확인 → 기기 빌드)을 넣었다. Codex standard 검토 1회에서 받은 7건을 모두 적용했다: 씬 빌더의 미저장 씬 확인·`SaveScene` 실패 전파, 호스트 Player Settings의 `Allow downloads over HTTP`를 `Development Only`로 변경, 패널 전체 스크롤로 작은 화면에서 내용이 밀리지 않게 함, 로그 메시지 한 줄 정규화, `GUI.matrix` 복원, 문서의 스크립트 경로 통일. 검토 중 확인한 예외 누출(평문 http LAN 주소에서 `SendWebRequest`가 던지는 `InvalidOperationException`)은 패키지 `PatchClient.SendAsync`에서 `PatchClientException`으로 감싸고 문서 실패 표에 추가했다.
- 검증: 임시 Editor 프로브로 `Allow downloads over HTTP` 동작을 실측했다. `Not allowed`에서 loopback은 200으로 성공하지만 LAN IP(`http://192.168.0.10:8765/`)는 `InvalidOperationException: Insecure connection not allowed`로 거부되고, `Development Only`로 바꾸면 같은 주소가 200(822바이트)으로 성공한다. 프로브는 검증 후 삭제했다. `serve-fixtures.sh`가 `manifests/0.json`을 200으로, 없는 경로를 404로 응답하는 것을 확인했다. 씬 재생성이 batchmode에서 성공하고 씬에 `_baseUrl`이 직렬화된 것을 확인했다. 에디터 PlayMode 12/12 통과, 컴파일 경고 0. 실제 모바일 기기 빌드는 수행하지 않았다.
