UPM 패키지 `src/GamePatchKit.Unity`(0.1.9)에 `PatchClient(baseUrl, rootPath).SyncAsync(releaseVersion, cancellationToken)`, `PatchSyncResult`, `PatchClientException`과 CLI `ManifestStore`·`DataExtractor`·`RelativePathValidator`·매니페스트 모델을 .NET Standard 2.1/C# 9로 옮긴 `Runtime/Core`, `ZstdSharp.dll`·`System.Runtime.CompilerServices.Unsafe.dll`(ZstdSharp netstandard2.1 의존성, Unity Player 프로필에 없음), `link.xml`, 서드파티 고지를 추가했다. 네트워크는 메인 스레드 `UnityWebRequest`(`DownloadHandlerFile`), 해시·해제는 `Task.Run`이며 취소는 캡처한 `SynchronizationContext`로 `Abort`를 보낸다. 로컬 배치·델타 규칙은 `gpk sync`와 같고 포인터는 읽지 않는다. ### 압축 미러 삭제와 진행 중 표식 도입

#### 사용자 입력

> 압축 미러는 삭제하는게 좋을거 같은데... 없으면 문제가 생기나?
>
> (grill-me) 그럼 동기화 성공후 지우는 쪽으로 변경해줘
>
> q1 롤백은 고려사항에 없어 그러니 그냥 전체 삭제하면 될 것 같아 / q2 성공 이후에 미러를 지우면 되지 않아? / q3 항상 삭제 해줘
>
> q2 예시를 알려줘
>
> 매니페스트는 삭제를 하는게 아니라 이름만 바꿔야해 우선 새 버전의 매니페스트를 {version}.json 형태로 로컬에 저장한 후에 성공하면 기존 매니패스트를 삭제하고 이름 변경. 기존 매니패스트 삭제 전에 비정상 종료가 되면 {version}.json이 있으면 정상 싱크가 됐는지 체크후 다운로드가 필요한 것이 있으면 받고 없으면 매니패스트로 이름 변경 이런식이 되어야해
>
> q2 같은 경우에는 우선 {version}.json 을 우선 받고 다음 최신 세대를 받게 되는 거지? / 니가 추천한대로 만들어줘

#### 작업 결과

- 수행: 먼저 미러 삭제의 영향을 코드로 조사해 보고했다. 미러를 읽는 곳은 다운로드 건너뛰기 판정과 해제뿐이고, `archives/`·`files/`를 지우는 코드가 없어 미참조 오버레이가 영구 누적되며, `compression: none` 그룹의 미러는 원본과 바이트가 같은 중복임을 확인했다. grilling 3라운드로 결정을 확정했다: 성공한 동기화 뒤 미러를 통째로 삭제(옵션 없음), 다운로드 대상을 "매니페스트 참조 전량"에서 "다시 풀어야 하는 엔트리가 읽을 산출물만"으로 변경, 중단된 세대를 먼저 완료하지 않고 요청한 세대로 곧장 이동. 사용자가 제시한 설계대로 해제 전에 `manifest.json`을 지우던 방식을 버리고, 목표 매니페스트를 `<세대>.json`으로 먼저 저장한 뒤 해제가 끝나면 `File.Replace`로 `manifest.json`에 올리도록 바꿨다. 같은 세대를 다시 요청하면 매니페스트도 이미 받은 산출물도 다시 받지 않는다. 건너뛰기 판정은 "로컬에 남아 있는 모든 매니페스트에서 identity가 목표와 같을 때만"으로 일반화했다. `ManifestStore`에 `PendingScan`·`ScanPending`·`CommitPending`·`GetPendingPath`를 추가하고 `DeleteLocal`을 제거했으며, `DataExtractor.Execute`가 매니페스트 목록을 받고 `CollectRequiredArtifacts`를 새로 노출한다. Codex adversarial 검토 2회를 거쳐 Blocker 2건을 반영했다: 완료된 `manifest.json`이 없으면 표식만으로 트리 내용을 보증할 수 없으므로 건너뛰기 근거를 비우고, 해석할 수 없는 `<세대>.json`은 읽는 시점에 지우지 않고 별도로 보고해 지름길을 막고 근거를 무효화한다. F3(`data/` 안 심볼릭 링크)은 계약 밖이라 거부하고 F4(`File.Replace` 플랫폼 지원)는 기기 검증 대상으로 보류했다. 2차 검토의 Medium 1건(회귀 테스트가 핵심 분기를 고정하지 못함)도 반영했다. 문서는 `docs/unity/patch-client.md`의 폴더 배치·결과·실패·직접 테스트 절과 설계 문서의 Q6 결정 뒤집기, `docs/project-description.md`를 갱신했다.
- 검증: 에디터 PlayMode 15/15, macOS IL2CPP Player 15/15 통과. 테스트가 헛돌지 않는 것을 mutation 6종으로 확인했다. 필요 산출물 필터 제거 3건 실패, 미러 삭제 제거 5건 실패, 표식 있을 때 지름길 허용 1건 실패, 완료 세대 없이 표식을 근거로 사용 1건 실패, 해석 못 하는 표식을 읽기에서 삭제 1건 실패, `UnreadablePaths` 조건만 제거 1건 실패. 각 mutation 복원 후 전부 통과했다. 픽스처 기준 다운로드량은 세대 0→1 업데이트 3개(아카이브 미포함), 세대 1→0 롤백 2개(아카이브 포함), 중단 후 같은 세대 재요청 1개(나머지 2개 재사용, 매니페스트 재요청 없음)다. 커밋은 하지 않았다.
