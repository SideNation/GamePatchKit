### 파일 객체 경로에서 버전 폴더를 없애고 파일 이름에 버전 부착

- 작업: `files/<그룹 id>/<파일 버전>/<상대 경로>`를 `files/<그룹 id>/<상대 경로>@<파일 버전>`으로 바꿨다. 마이너 변경은 파일 몇 개만 건드리는데 버전 폴더 방식은 매번 파일 하나짜리 폴더 트리를 만든다.
- 작업: 버전을 원본 이름 뒤에 붙여 확장자를 쪼개지 않도록 규정했다. `.tar.gz`나 확장자 없는 파일도 같은 규칙으로 처리된다.
- 작업: 규칙 서술 2곳, 출력 레이아웃, 예시 2·3·4·7의 경로를 모두 갱신했다.

### 파일 객체 경로에 그룹 버전 폴더 복원

- 작업: 경로를 `files/<그룹 id>/<그룹 버전>/<상대 경로>@<파일 버전>`으로 확정했다. 폴더는 그룹 버전(메이저)까지만 나누고 리비전은 파일 이름에만 붙는다.
- 작업: 그룹 버전 폴더의 목적을 세대 단위 삭제로 문서에 명시했다. 그룹 버전을 올리면 새 세대가 새 폴더에 쌓이므로 이전 세대를 폴더째 지울 수 있다.

### 버전 구분자를 @에서 .v로 변경

- 작업: `@`가 안전한지 확인했다. Windows·macOS·Linux 파일 시스템과 .NET에서는 문제가 없고 RFC 3986도 path segment에서 `@`를 허용한다. 다만 AWS S3 객체 키 가이드가 `@`를 "특별 처리가 필요한 문자"로 지정하고 있다.
- 작업: 구분자를 `.v`로 바꿨다. `.`과 `v`만 쓰므로 RFC 3986 unreserved와 S3 safe 문자 집합에 모두 들어간다. `~`는 S3가 회피 대상으로 지정해 후보에서 제외했다.
- 작업: 규칙 2곳, 출력 레이아웃, 예시 경로 전체를 갱신하고 선택 근거를 PRD에 남겼다.

- 수행: 최초 빌드→무변경→수정→재수정→추가→삭제→그룹 버전 증가 흐름의 단계별 매니페스트·산출물 집합·요약을 하나의 임시 Git 저장소에서 검증했다. 다중 그룹 합계와 여러 리비전 조정, source 아래 untracked 파일과 source 바깥 tracked 변경의 제외도 고정했다.
- 수행: 마지막 그룹의 아카이브 충돌로 앞 그룹 산출물 작성 후 실패를 재현해 기존 매니페스트 바이트와 마지막 성공 `sourceCommit` 보존, 동일 미참조 산출물 재사용, 실패 구간 재계산을 검증했다. 후보가 달라진 아카이브는 yaml 그룹 버전을 올린 뒤 다른 증분 그룹의 실패 구간까지 함께 반영되는 복구 흐름도 추가했다.
- 수행: `gpk build` 사용법, 성공 요약 필드, 리비전 경고, 실패 후 남는 미참조 객체와 재실행 규칙을 `docs/cli/build.md`에 기록했다.
- 검증: Release xUnit 99개, `dotnet format --verify-no-changes`, 이번 변경 범위의 공백 검사와 NuGet pack이 통과했다. adversarial 단독 검토 3회에서 루프 내 문자열 결합, zstd 실제 저장 바이트 검증, 단계별 산출물 집합, 다중 그룹 합계 검증을 보완했고 남은 finding은 없다. 패키지 readme 권장 경고는 계획대로 P10에서 처리한다.

#### 작업 결과
