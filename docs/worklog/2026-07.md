### ✅ 수정/구현: release 식별 계약 단순화

**배경:** `releaseId` 계산 입력에서 manifest schema version이 빠지면 같은 불변 경로에
서로 다른 manifest byte가 충돌할 수 있었다.

**수정:**

- `releaseId`를 제거하고 canonical manifest 원본 byte의 SHA-256인 `manifestHash`를
  불변 manifest 식별자로 사용한다.
- manifest 내부에는 `manifestHash`를 기록하지 않으며 channel과 Runtime current
  pointer가 `manifestHash`를 보유한다.
- `compactVersion`은 최초 package `0`, incremental 상속, compact 시 `+1`로 정의한다.
- 사용자의 명시적 지시에 따라 PRD는 `개발 v2`를 추가하지 않고 기존 `개발 v1` 본문을
  직접 갱신했다.

### ✅ 수정/구현: incremental artifact 재사용 조건 명확화

**배경:** 경로와 `fileHash`만 같은 기존 bundle 참조를 group·`artifactMode` 변경 뒤에도
재사용하면 file group과 bundle group 경계가 깨질 수 있었다.

**수정:**

- 기존 file artifact는 group·`artifactMode`·compression 설정이 바뀌어도 file
  override로 재사용한다.
- 기존 bundle은 group이 유지되고 현재 `artifactMode`도 `bundle`일 때만 재사용하며,
  그 외에는 file artifact override로 전환한다.
- compression은 새 artifact 생성 정책으로 한정하고, 설정이 바뀌어도 기존 artifact의
  payload와 실제 compression metadata를 그대로 재사용한다.
- 같은 release 안의 혼합 compression과 재사용 codec 지원 요구를 PRD·Runtime·문서화
  계획에 반영했다.

### ✅ 수정/구현: optional group과 `PackageState` 계약

**배경:** 최초 plan에서 optional group을 다운로드하지 않으면서도, 전역 release 갱신과
나중의 optional 설치가 어떤 manifest를 기준으로 동작하는지 로컬에 일관되게 기록할
명세가 필요했다.

**수정:**

- 최초 설치와 전역 release 갱신은 required group만 다운로드하고, optional group은 현재
  active manifest를 기준으로 요청 시 별도 설치한다.
- package별 `PackageState` 하나에 전역 active pointer와 group별
  `ready`·`notInstalled`·`stale` 상태를 기록한다.
- 변경되지 않은 optional group은 다운로드 없이 새 active manifest에 재연결하고,
  변경된 optional group은 기존 byte를 보존하되 `stale`로 만들어 노출하지 않는다.
- `PackageState` v1 필드 형식과 불변 조건, opaque `installationKey`, 최초 state 구성,
  writer lock, immutable installation과 원자적 state 교체 순서를 명시했다.
- 손상된 state는 cache 경로만 보고 활성 버전을 추정하지 않으며, host가 제공한 신뢰
  가능한 target pointer를 기준으로만 재구성한다.
- PRD 검증 기준 22·23과 Runtime·DotNet·adapter conformance·문서화 계획을 연결했다.
- 사용자의 명시적 지시에 따라 새 `개발 v2`를 만들지 않고 `개발 v1`을 직접 수정했다.

### ✅ 수정/구현: multi-group activation batch 원자성

**배경:** 여러 group을 한 요청으로 다운로드할 때 group마다 `PackageState`를 commit하면
일부 group만 `ready`인 중간 상태가 노출될 수 있었다.

**수정:**

- 한 Runtime 요청의 target group 집합을 하나의 activation batch로 정의했다.
- group별 다운로드·검증·staging은 병렬로 허용하지만 committed state는 변경하지 않는다.
- 모든 group의 immutable installation 승격 후 `PackageState` 전체를 한 번만 교체하고
  `stateRevision`도 한 번만 증가시킨다.
- 한 group 실패 시 batch 전체가 이전 state를 유지하며, commit 직전
  `active.manifestHash`·`stateRevision` 충돌 시 최신 state 기준으로 재계획한다.
- Runtime·DotNet·adapter conformance에 부분 활성화 방지와 단일 commit 검증을 추가했다.

**파일:** `docs/prd/game-patch-kit-prd.md`, `docs/plan/08-runtime.md`,

### ✅ 수정/구현: `gamepatchkit.yml` 입력 범위와 schema 역할

**배경:** 사용자 입력 설정, 설정 검증 schema와 Packager 생성 manifest의 역할이
혼동될 수 있었고 YAML 고급 기능의 지원 범위가 정해지지 않았다.

**수정:**

- `gamepatchkit.yml`은 사용자가 작성하는 설정, `package-config.schema.json`은 YAML
  파싱 결과를 검증하는 versioned 배포 계약, release manifest는 Packager가 생성하는
  canonical JSON으로 구분했다.
- YAML은 정확히 하나의 non-empty document와 mapping root만 허용한다.
- anchor·alias·merge key·custom tag·중복 mapping key와 다중 document를 거부한다.
- YAML 문법 검증 → JSON-compatible 데이터 변환 → schema 검증 → 모델 의미 검증
  순서를 고정했다.
- PRD 검증 기준 24와 Schema·CLI·문서화 계획을 연결했다.
